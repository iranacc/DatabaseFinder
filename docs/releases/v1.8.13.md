# Database Finder v1.8.13

## فارسی

این نسخه دکمهٔ «انتخاب پوشه دستی...» در صفحهٔ *کپی فایل فیزیکی دیتابیس* را ایمن می‌کند. مسیر دستی برای زمانی است که فایل‌های واقعی دیتابیس پیدا نشده‌اند یا دسترسی به آن‌ها نداریم، بنابراین هر سکوت یا رفتار غیرقابل‌پیش‌بینی در این مسیر می‌توانست باعث شود پرونده‌ای ناقص یا بی‌صدا خراب شود.

### اصلاحات کپی با مسیر دستی

- **پایان کپی انفجاری:** پوشه‌هایی که حاوی لینک یا Junction هستند (مثل ریشهٔ یک دیسک یا پوشه‌های حاوی `Application Data`) دیگر بی‌نهایت تکرار نمی‌شوند. لینک‌ها دنبال نمی‌شوند و هر کدام جداگانه به‌عنوان «کپی نشد» در لاگ و مانیفست ثبت می‌شوند.
- **سقف عمق:** تودرتویی بیش از ۲۴ سطح با پیام روشن متوقف می‌شود.
- **رعایت فایل‌های قفل:** در مسیر دستی هم مانند مسیر خودکار، اگر حالت «Shadow Copy» انتخاب شده باشد فایل‌های قفل از طریق VSS کپی می‌شوند؛ در غیر این صورت پیام «سرویس باید متوقف شود» داده می‌شود.
- **پوشهٔ ناموجود دیگر بی‌صدا رد نمی‌شود:** اگر پوشهٔ انتخاب‌شده حذف، تغییر نام یا قطع شده باشد، خطای صریح ثبت و آن دیتابیس ناموفق شمرده می‌شود.
- **زیرپوشهٔ غیرقابل‌خواندن کل دیتابیس را از کار نمی‌اندازد:** خطا فقط برای همان زیرپوشه ثبت می‌شود و بقیهٔ فایل‌های همان دیتابیس کپی می‌شوند. پیام‌ها فارسی و ترجمه‌شده‌اند.
- **برآورد فضای دیسک:** پیش از شروع کپی، اندازهٔ واقعی پوشه‌های دستی شمرده می‌شود؛ پیش‌تر برای این مسیرها صفر برآورد می‌شد و هشدار «فضا کافی نیست» هرگز داده نمی‌شد. شمارش در پس‌زمینه انجام می‌شود تا رابط کاربری قفل نشود.
- **نوار پیشرفت** برای کپی پوشه‌ای بر اساس فایل‌های واقعی به‌روزرسانی می‌شود.
- **قفل کنترل‌ها حین مأموریت:** در طول کپی، دکمه‌های انتخاب پوشهٔ دستی، انتخاب همه/هیچ، جست‌وجوی رمز، اعطای دسترسی، اسکن عمیق، اسکریپت آزمایشگاه، انتخاب مقصد و درخت نتایج غیرفعال می‌شوند تا وضعیت مأموریت وسط کار تغییر نکند. پس از پایان، وضعیت قبلی هر کنترل بازگردانده می‌شود.

### تجربهٔ کاربری دکمه

- اگر دیتابیس از قبل مسیر دستی دارد، تعویض پوشه دیگر دوباره پیام «جایگزینی فایل‌های خودکار؟» را نشان نمی‌دهد.
- اگر همان پوشه مسیر دستی چند دیتابیس دیگر هم باشد، پیش از ثبت هشدار داده می‌شود که داده دو بار کپی خواهد شد.
- مرورگر انتخاب پوشه از جای مرتبط باز می‌شود: مسیر دستی فعلی، پوشهٔ فایل‌های پیدا‌شده، پوشهٔ فایل آفلاین یا در نهایت مقصد؛ نه به‌صورت پیش‌فرض روی پوشهٔ مقصد.
- مسیر دستی نامعتبر نادیده گرفته می‌شود و مرورگر به پوشهٔ بعدی معتبر می‌رود.

### تغییرات فنی

- پیمایش درخت پوشه به یک پیاده‌سازی امن با پشتهٔ صریح، حذف `ReparsePoint` و سقف عمق تغییر کرد.
- `DatabaseFileLocator.EstimateRequiredBytes` برای برآورد فضا اضافه شد.
- هشت کلید ترجمهٔ جدید در هر دو زبان فارسی و انگلیسی اضافه شد.
- نسخهٔ اسمبلی و فایل به `1.8.13` افزایش یافت.
- checksum فایل‌های Release به‌روزرسانی شد.

## English

This release hardens the "Choose folder manually..." action in the *Copy physical database files* screen. A manual path is the fallback when the real database files cannot be located or accessed, so any silence or unpredictable behaviour on that path could quietly damage an incomplete case file.

### Manual-folder copy fixes

- **Runaway copies stopped:** folders containing links or junctions (drive roots, folders with `Application Data`-style links) no longer multiply without limit. Links are not followed and each one is reported as "not copied" in the log and the manifest.
- **Depth cap:** nesting deeper than 24 levels stops with a clear message.
- **Locked files honoured:** with the Shadow Copy option selected, locked files in a manual folder are now copied through VSS, exactly like auto-located files; otherwise the "stop the service" message is shown.
- **A missing folder is never skipped silently:** if the chosen folder was deleted, renamed or disconnected, an explicit error is recorded and the database is counted as failed.
- **An unreadable subfolder no longer aborts the whole database:** the failure is recorded for that subfolder only and the remaining files of the same database are copied. Messages are localised.
- **Free-space estimate:** the real size of manual folders is measured before the copy starts. It used to estimate zero for these paths, so the "not enough space" warning could never fire. The measurement runs in the background so the UI stays responsive.
- **Progress bar** now advances per real file for folder copies.
- **Planning controls locked during the operation:** while copying, the manual-folder action, select/clear all, password finder, admin grant, deep sweep, lab script, destination picker and the results tree are disabled so the mission state cannot change mid-run. Each control's previous state is restored afterwards.

### Action user experience

- Re-picking a folder for a database that already has a manual path no longer shows the "replace auto-located files?" prompt again.
- Choosing a folder that is already the manual folder of other databases now warns that their data will be copied a second time.
- The folder browser opens where the database files actually are: the current manual path, the folder of the located files, the offline file's folder, or the destination as a last resort - instead of always starting at the destination.
- A stale manual path is skipped and the browser moves on to the next valid candidate.

### Technical changes

- Folder traversal was replaced with a safe implementation using an explicit stack, `ReparsePoint` skipping and a depth cap.
- Added `DatabaseFileLocator.EstimateRequiredBytes` for the space pre-check.
- Added eight new translation keys in both Persian and English.
- Bumped assembly and file version metadata to `1.8.13`.
- Updated Release checksums.
